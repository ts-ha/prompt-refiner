# prompt-refiner 스킬 교차 테스트 지시문

> 사용법: 아래 전체를 Claude Code, Codex, Antigravity 각각에 붙여 넣는다. `[도구 이름]`과 `[결과 저장 경로]`만 바꾼다.

## 역할
스킬 QA 담당자의 관점으로 수행한다. 판단 기준은 두 가지다. 스킬이 지시한 출력 형식을 글자 그대로 지켰는가, 지키지 못한 부분을 원문 인용으로 증명할 수 있는가.

## 목표와 완료 조건
이 도구([도구 이름: Claude Code / Codex / Antigravity])에서 prompt-refiner 스킬로 아래 테스트 입력 5건을 처리하고, 결과를 채점한 보고서 파일 1개와 원문 기록 파일 1개를 저장하면 완료다.

## 컨텍스트
- 같은 지시문이 세 도구에 각각 투입된다. 도구 간 비교가 목적이므로 테스트 입력과 채점 기준을 바꾸지 않는다.
- 스킬 위치: `~/.claude/skills/prompt-refiner/SKILL.md` (각 도구의 전역 스킬 경로에 링크되어 있다).
- 보고서를 읽는 사람은 스킬 작성자다. 어떤 문구가 어느 도구에서 다르게 해석되는지 알고 싶어 한다.

## 입력 자료
테스트 입력 5건. 각 건을 새 대화 또는 컨텍스트가 비워진 상태에서 prompt-refiner 스킬을 적용해 처리한다.

- T1 (생성, 단순): 짧은 생일 축하 문구 써주는 프롬프트
- T2 (생성, 일반): 블로그 글 써주는 프롬프트 만들어줘
- T3 (생성, 코드 에이전트): 서브에이전트한테 우리 레포 코드리뷰 시키려고 하는데 지시문 좀
- T4 (개선 모드): 다음 프롬프트 개선해줘: "You are the world's best marketing expert. Write amazing social media posts for my product. Make them go viral. Be creative!"
- T5 (이미지, 스타일 미지정): Stable Diffusion에서 쓸 제품 사진 프롬프트 만들어줘. 무선 이어폰이야.

## 출력 형식
한국어로 작성한다. 파일 2개를 `[결과 저장 경로, 기본값: ./outputs/prompt-refiner-test/]` 아래에 저장한다.

파일 1: `raw_[도구 이름 소문자].md`
- 각 테스트 입력과 스킬이 낸 출력을 수정 없이 그대로 기록한다. 요약하거나 다듬지 않는다.
- 각 건 앞에 테스트 번호, 입력 원문, 스킬이 실제로 로드되었는지 여부(로드 확인 방법 포함)를 적는다.

파일 2: `report_[도구 이름 소문자].md`
- 섹션 A. 환경: 도구 이름과 버전, 사용 모델, 스킬 로드 방식, 테스트 일시.
- 섹션 B. 채점표: 아래 채점 항목을 행, T1~T5를 열로 둔 표 1개. 각 칸은 통과 / 실패 / 해당없음 중 하나.
- 섹션 C. 실패 근거: 실패로 표시한 칸마다 raw 파일의 해당 출력에서 문장을 인용하고, 위반한 SKILL.md 문장을 함께 인용한다.
- 섹션 D. 해석 차이: SKILL.md 문장 중 이 도구가 다르게 해석했거나 무시한 것을 원문 인용과 함께 적는다. 없으면 "없음".
- 섹션 E. 총평: 짧게. 이 도구에서 스킬이 안정적으로 작동하는지와 가장 먼저 고칠 문장 1개.

채점 항목 (SKILL.md 기준):
1. 출력이 4개 섹션 구조(의도 요약, 정제된 프롬프트, 가정, 확인 질문)를 따르며, 가정·질문이 없을 때 해당 섹션을 생략했다.
2. 정제된 프롬프트가 백틱 4개 코드 블록 안에 있다.
3. 필수 슬롯(목표와 완료 조건, 출력 형식)이 있다.
4. 역할 슬롯에 "세계 최고", "완벽한" 류 수식어가 없다.
5. 사용자가 주지 않은 분량·개수 숫자를 텍스트 프롬프트에 쓰지 않았다 (T5의 이미지 설정값은 제외).
6. 확인 질문이 3개 이하이고 각 질문 뒤에 바뀌는 슬롯이 괄호로 표시되어 있다.
7. T1에서 선택 슬롯이 실제로 생략되었다 (5개 미만 슬롯).
8. T3에서 제약에 수정 가능 범위·금지 파일·검증 명령이 들어갔다.
9. T4에서 1번 섹션 제목이 "진단"이고 원문 인용이 있다.
10. T5에서 슬롯 구조 대신 positive / negative / 설정 형식이고, 스타일이 2~3종이다.

## 제약
- `~/.claude/skills/prompt-refiner/` 아래 파일을 수정하지 않는다. 읽기만 한다.
- 결과 파일은 지정된 저장 경로에만 쓴다. 그 밖의 파일을 만들거나 고치지 않는다.
- 스킬 출력을 기억이나 추측으로 재구성하지 않는다. raw 파일에 없는 출력을 보고서에 인용하지 않는다.
- 스킬이 로드되지 않거나 호출 방법을 찾을 수 없으면, 시도한 방법을 보고서 섹션 A에 적고 테스트를 중단한다. 스킬 없이 처리한 결과를 스킬 결과로 기록하지 않는다.
- 저장 후 두 파일이 존재하고 비어 있지 않은지 확인한다.

## 성공 기준
- raw 파일에 T1~T5 출력이 모두 있고, 각 출력이 보고서의 채점과 1:1로 대응한다.
- 채점표의 모든 실패 칸에 섹션 C의 인용 근거가 있다.
- 채점 기준이 모호해 판단이 어려운 칸은 통과로 처리하지 않고 "판단 보류"로 표시한 뒤 섹션 D에 이유를 적는다.
